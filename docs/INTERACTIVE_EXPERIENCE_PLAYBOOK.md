# Interactive Experience Playbook
**Version:** 1.0 | **Prepared:** 9 October 2026  
**Purpose:** Establish River Ways as a practitioner of useful, distinctive, social-aware creative interaction—without sacrificing accessibility, speed, substance, privacy, or conversion.

## 1. Strategic point of view: from page to useful experience

Social platforms have trained people to expect fast hooks, clear payoffs, media-rich explanations, personal relevance, interactive participation, and content they can share. The lesson is not to turn every website into a feed. A website should do what social feeds often cannot: provide ownership of the journey, depth, context, reliable navigation, a useful tool, a direct next step and a relationship with the brand.

**Working model:** Hook → Explore → Personalise → Discover value → Save/share → Continue → Convert (only when ready).

The hook earns attention; the experience rewards attention. If an experience uses a strong visual opening but withholds its value, blocks browsing, or needs a giant script to run, it has failed the model.

## 2. Interaction strategy: each technique needs a job

| Pattern | Use when | Examples for River Ways and client work | Avoid |
|---|---|---|---|
| Scroll-led storytelling | The order of information genuinely matters | Show how a market signal becomes an opportunity, step by step | Long scroll lock, motion that hides copy or delays navigation |
| Tap/drag-to-explore diagram | A system is easier to understand spatially | Demand Engineering engine, service map, lead journey | Tiny targets or diagram-only content with no text equivalent |
| Guided quiz/diagnostic | Answers change the recommendation | Growth-readiness score, website brief, brand discovery | Fake precision, opaque score, unnecessary personal data |
| Slider/calculator | Users benefit from changing assumptions | Funnel leakage model, service budget planning, scenario forecasts | Presenting assumptions as fact or claiming a prediction is guaranteed |
| Configurator | A set of choices changes an output | Website scope builder, campaign mix explorer, package pathways | Hiding total cost or manipulating choices toward an undisclosed upsell |
| Interactive case study | Process and decisions are as important as the result | Challenge → insight → intervention → evidence → lessons | Unverified metrics or fabricated client evidence |
| Search/filter experience | A content library has enough useful material | Resource finder, service selector, portfolio filter | Filters that return empty pages or use inaccessible custom controls |
| Product simulation | A live concept needs demonstration | Demand signal inbox with clearly labelled illustrative records | Calling simulated data live, implying source integrations exist when absent |
| Data visualisation | Relationships or change reveal insight | Anonymous aggregate campaign/funnel data with provenance | Charts without textual summary, misleading axes or unlabelled source/date |
| Personalised route | A visitor's industry or goal materially changes next steps | “I need more demand” → recommended diagnostic and service | Secret profiling, unexplained personalisation, blocking the main site |
| Shareable artifact | The visitor gets something genuinely useful | Downloadable summary, scorecard, brief, chart, report | Making sharing mandatory or exposing private answers in a public URL |
| Conversation assistant | The task is ambiguous and conversational guidance helps | Guided brief intake, resource discovery | Replacing clear service descriptions, trapping the user, pretending to be human |
| Motion/3D/WebGL | Spatial or narrative movement adds understanding | Product demo, brand reveal, interactive system object | Motion for its own sake, slow mobile, battery cost, no reduced-motion fallback |
| Before/after comparison | Changes are visible and meaningful | Website audit snapshots, conversion journey mapping | Implying results were measured when visual comparison is a concept only |
| Live/real-time data | Fresh data adds real user value | Approved alerts, status indicator, timely trend chart | Unexplained tracking, no timestamp, no stale/error mode |

## 3. Creative standards: film craft meets product clarity

### Design from the hook, not only the hero image
- Open with one clear idea and a meaningful visual.
- Use real interfaces, products, diagrams, numbers or people only when they substantiate the story.
- Use strong typography, pacing, whitespace, selective colour, composition and transition logic.
- Keep the user interface calm while the story or imagery may be expressive.
- Create an intentional first 2–5 seconds for social videos, but do not make website users wait through a branded intro before they can act.
- Design assets in reusable variants: landscape for site/YouTube, 9:16 for Reels/Shorts/TikTok, 1:1 where appropriate, short looping cut, poster frame, captions and reduced-motion/static alternative.

### Use inspiration responsibly
Raylight.app is a reference for product-video composition, templated motion, shot timing and iterative render/inspect/correct workflows. Apple's HIG is a reference for purposeful, brief and optional motion. Figma, Apple, Linear, Stripe and award galleries are references for different parts of the craft—not templates to replicate. Record the exact feature being studied and build an original River Ways expression.

### Original interaction grammar
Develop a recognisable grammar rather than arbitrary animations:
- **Signal:** a subtle lime point or line appears where meaningful information is detected.
- **Connection:** lines/paths show relationships between inputs and outcomes.
- **Qualification:** a signal gains context and moves through a deliberate decision.
- **Activation:** the user can choose, edit, or act.
- **Learning:** feedback closes the loop with evidence, not an empty animation.
This can guide transitions, illustrations, diagrams, loading states and educational content without forcing the brand mark into every component.

## 4. Social-to-site-to-social loop

Create a loop in which social content invites a useful website experience and the website generates a meaningful output that can travel back into social channels.

1. **Social trigger:** short video, carousel, question, before/after (only substantiated), useful observation or industry-specific problem.
2. **Landing experience:** page matches the promise and provides a clear, low-friction next step.
3. **Participation:** visitor uses a diagnostic, calculator, selector, interactive explanation or resource.
4. **Value:** produce a useful insight, personalised next-step plan or shareable summary.
5. **Permission-based continuation:** offer download, email follow-up, consultation, or save/share functionality with clear terms.
6. **Learning loop:** measure completion, friction and qualified outcomes; change one variable at a time where practical.
7. **Return to social:** repurpose the method or anonymised aggregate findings as educational material, not as private user data.

Do not build a comment-feed clone, engagement bait, addictive streaks or algorithmic content stream just because they are familiar. A small interactive experience that helps someone finish a task is often more valuable than many superficial widgets.

## 5. River Ways interactive product roadmap

### First experiences to build
1. **Demand Engineering Explorer:** a clear interactive map linking strategy, audience, discovery, content, paid activation, conversion and measurement.
2. **Growth Readiness Diagnostic:** approximately 8–12 well-designed questions across positioning, discovery, conversion, measurement and follow-up. Score transparently, return three priority improvements, explain that the result is directional, and offer a next step.
3. **Website Opportunity Mapper:** collect a goal and current constraints; generate a prioritised project brief. No access to third-party accounts needed in v1.
4. **Demand Intelligence Sandbox:** use synthetic records with a persistent “DEMO / SAMPLE DATA” label to demonstrate signal → context → qualification → alert → human follow-up.
5. **Service Fit Navigator:** let a visitor choose a challenge, audience, timeline and expected deliverable; map to the most relevant service page.
6. **Interactive Case Study Template:** build a reusable story with problem, hypotheses, work, evidence, lessons and source notes.

### Later, after the foundation is reliable
- Secure live intent-monitoring dashboard and alert routing.
- CRM-connected website brief and qualification workflow.
- Multi-user project portal for client delivery.
- Reporting workspace for campaign and discovery signals.
- Saved/revisitable assessments if authentication and retention justify the complexity.
- Industry-specific calculators where buyers have a clear need and inputs can be sourced or disclosed.

## 6. Niche-specific interactive tool ideas

| Niche | High-value tool | What the visitor gets | Data discipline |
|---|---|---|---|
| B2B/professional services | Lead journey or pipeline leakage diagnostic | Prioritised journey bottlenecks | Make conversion assumptions editable |
| SaaS/technology | Trial-to-paid journey planner or feature explorer | Suggested lifecycle improvements | Label benchmark values and sample data |
| E-commerce/retail | Product finder, comparison, fit quiz, basket or delivery estimator | Lower decision friction | Keep price/stock/delivery current and sourced |
| Property/real estate | Location/property brief, affordability or rental scenario planner | Filtered shortlist or buying brief | Show assumptions and relevant local disclaimers |
| Healthcare/clinics | Appointment routing and service eligibility explainer | Correct department and next step | Avoid diagnosis; protect health data; provide appropriate care guidance |
| Education/training | Course finder, readiness assessment, curriculum explorer | Relevant course options and requirements | Avoid guaranteed employment/outcome claims |
| Finance/insurance | Needs checklist, cost scenario, product explainer | Better informed comparison | Regulatory review; clear assumptions; not personalised advice unless authorised |
| Hospitality/travel | Trip builder, availability route, itinerary selector | Practical options | Display current availability and pricing sources |
| Logistics/manufacturing | Service configuration, route/operations assessment | Qualified brief or estimate | Clarify operational assumptions, regions and service constraints |
| Legal/accounting | Matter/service triage and document checklist | Correct service pathway | Avoid implying legal/tax advice or creating unjustified confidentiality promises |
| NGO/public-impact | Impact explorer, programme eligibility and outcome visualisation | More transparent choices | Methodology and data provenance visible |
| Home/field services | Problem-to-service selector and quote brief | Better prepared enquiry | Estimates labelled; safety-sensitive cases handled carefully |

Select only tools validated by real sales conversations, keyword research, customer tasks and operational feasibility. Each tool needs an owner, measurable purpose, data source, privacy classification and maintenance budget.

## 7. UX and accessibility contract for creative interactions

Each pattern must handle:
- Mouse, keyboard, touch and assistive technology.
- Visible focus, logical focus order and accessible names.
- Text equivalents for canvas, charts, visual-only states and key animations.
- Reduced motion using `prefers-reduced-motion`; no critical action depends on animation.
- Narrow viewports, large text/zoom, orientation changes and slow connections.
- Loading, empty, partial, offline, error and retry cases.
- Back/forward navigation, deep links and direct page access.
- Clear outcomes and a way to restart, revise, cancel, save or exit where applicable.
- No automatic audio, forced autoplay, scroll trapping or inaccessible gesture-only action.
- No collection of sensitive data unless necessary, justified, protected and properly disclosed.

Use semantic HTML for core information and controls. ARIA should add needed semantics, not cover up missing HTML semantics. Follow the WAI-ARIA Authoring Practices when implementing custom tabs, dialogs, menus and comboboxes.

## 8. Performance and motion budget

- Prefer CSS/SVG/canvas only when appropriate and simple enough to maintain.
- Lazy-load below-the-fold media; set width/height or aspect ratio to reserve space.
- Prefer responsive compressed image formats and poster images for video.
- Avoid loading Three.js/WebGL or large animation runtimes globally if only one page uses them; load them on demand.
- Provide a reduced-motion and low-power fallback; no large animation dependency for content that can be a small CSS transition.
- Check frame rate, mobile device heat/battery impact, JS evaluation and interaction responsiveness.
- Keep font families/weights deliberate and avoid unnecessary external requests.
- The page must remain understandable if a third-party embed or motion library fails.

Core Web Vitals starting targets (measured with real field data at the 75th percentile): LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1. Establish separate lab budgets for JavaScript, images, video and render work based on test results.

## 9. Experiment and learn

For each new experience, document:
- Hypothesis: what user problem exists and why this pattern should solve it.
- Audience and entry source.
- Main task and expected output.
- Primary success metric and guardrail metrics.
- Smallest useful version.
- Performance, accessibility, privacy and security risk.
- Baseline and rollout plan.
- Result, limitations, learning and next decision.

Measure tool-start rate, completion rate, abandonment point, output usefulness, qualified CTA click, submitted lead rate, lead quality, return use and performance. Never optimise completion at the expense of trust, consent or lead quality.

## 10. Design-to-build protocol
1. Define task and hypothesis.
2. Sketch journey and content states.
3. Prototype in Figma if visual/interaction complexity justifies it.
4. Use real River Ways tokens/components and explicit states.
5. Implement the smallest complete experience.
6. Test using browser automation plus manual keyboard/mobile review.
7. Validate performance, privacy and accessible alternatives.
8. Test the live preview and collect evidence.
9. Release behind a reversible change where practicable.
10. Review usage and outcomes, then revise.
