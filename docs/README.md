# River Ways Website Governance and Resource Hub
**Current edition:** 1.0 | **Reviewed:** 9 October 2026

This folder is the working knowledge base for turning River Ways into a benchmark for creative, interactive, accessible, secure and commercially effective websites. It also provides reusable standards for client engagements across relevant niches.

## How the documents work together

- The root [AGENTS.md](../AGENTS.md) provides repository-specific operating rules for AI agents and developers; the [pull-request template](../.github/PULL_REQUEST_TEMPLATE.md) makes release evidence part of the review workflow.
- The Constitution states **what must be true**.
- The Reference Library states **where to research and verify**.
- The Interactive and Content playbooks state **what kinds of experiences to build and why**.
- The Niche playbooks adapt the standards to **different audiences and risks**.
- The MCP standard governs **how AI tools may assist safely**.
- The SEO and Security documents define the applicable specialist constraints.
- The QA gates define **how to prove the work is ready**.
- The Roadmap turns the standards into **prioritised implementation work**.

## How to use this system on a client website

Create a client-specific copy or project plan based on these standards. Preserve the reusable minimums for security, accessibility, performance, privacy, evidence and release quality. Tailor brand, user journeys, content, tools, niche and measurable goals to that client's actual business. Do not blindly copy River Ways' colours, positioning, visual style or service architecture onto another brand.

## Research and evidence policy

- Research was reviewed on 9 October 2026; sources may change.
- Primary standards and official vendor documentation take precedence over galleries, blogs and community examples for implementation decisions.
- Inspiration sources are not proof of conversion performance, accessibility, legal rights or security.
- Tool/vendor listings are candidates, not procurement approvals. Verify costs, plan access, licence, API/terms, data coverage and privacy before use.
- The catalogue is comprehensive for the identified workstreams but cannot literally include every website, article or MCP server in the open web. It is a versioned, maintainable resource pool with a source-admission process.
- Record the source, exact claim/feature, date checked, implementation relevance, rights/limitations and review owner for new references.
- Never publish fabricated client proof, metrics, awards, testimonials, certifications, capabilities or integrations.
- Treat AI-generated source summaries, code and design as unverified drafts until reviewed and tested.

## Current operational caution

The redesign remains a test project until its actual deployment, full user journeys and release checks are verified. The existing live website and its domain/email/DNS infrastructure must remain intact until an explicitly approved production migration. Do not assume a successful build or the presence of a security configuration file means the live deployment is secure or the enquiry pipeline works end to end.
