## 7. Security and privacy caution

Do not use temporary email, self-destructing notes, anonymous file-sharing or untrusted upload services for River Ways credentials, client data, private briefs, leads, source code or production secrets. This includes Temp-Mail, 10 Minute Mail, Privnote and File.io. Prefer approved storage, access controls and auditable sharing. Treat third-party AI agents, MCP servers, skills and repositories as untrusted until source, permissions, network access, data handling and licence have been reviewed.

## 8. Implementation rules

1. Start with P0/P1 resources; do not install the entire list.
2. Check availability, maintenance, licence, pricing and permissions before adoption.
3. Use references to extract principles; create original River Ways compositions.
4. Every dependency must justify bundle size, performance impact, maintenance cost and accessibility.
5. Test mobile, keyboard, reduced motion and lower-powered devices.
6. Do not add sound, shaders, 3D or scroll effects merely because a tool makes them easy.
7. Record what was adopted or rejected, why, and where it appears.
8. No production deployment, DNS, secrets or destructive repository changes without explicit approval and release verification.

## 9. First adoption sequence

- P0: Create a River Ways design brief / getdesign.md equivalent grounded in SHAPED CURRENT, the River philosophy, buyer journeys, conversion and accessibility.
- P1: Curate a reference board using ScrollTide, Motion in Design, Land-book, 60fps, Styles Refero, Fontshare and Easings.
- P1: Prototype one signature hero interaction with a static/reduced-motion alternative.
- P1: Evaluate existing React/CSS capabilities before adding Motion or GSAP.
- P2: Evaluate Three.js only if a 2D prototype cannot achieve the intended experience.
- P1: Verify changes with Playwright, accessibility checks and performance measurements.
