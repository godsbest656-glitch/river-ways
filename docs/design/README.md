# River Ways Design Foundation

This folder is the design source of truth for the AI developer and human reviewers. It provides guardrails and a repeatable process—not a premature final identity. The AI developer should use it to research, propose, test, and implement a coherent system.

## Read in this order
1. [Design Constitution](./DESIGN_CONSTITUTION.md) — principles and non-negotiable quality bar.
2. [Creative Direction Brief](./CREATIVE_DIRECTION_BRIEF.md) — strategic intent, audience, creative tensions, and research questions.
3. [Design System Architecture](./DESIGN_SYSTEM_ARCHITECTURE.md) — tokens, components, layout, motion, and code organization.
4. [Design Agent Protocol](./DESIGN_AGENT_PROTOCOL.md) — how to research, make decisions, document, and implement.
5. [Design Acceptance Gates](./DESIGN_ACCEPTANCE_GATES.md) — measurable review criteria and stop/go conditions.

## Required working sequence
**Audit → evidence-led research → competing routes → prototype → critique → design system → page implementation → validation.**

Do not jump directly from a prompt to a complete homepage. Do not treat inspiration screenshots as permission to copy them. Do not lock palette, type, logo, or motion language before comparing distinct routes against the same criteria.

## Decision status
No final logo, color palette, typography pairing, art direction, page architecture, or animation specification is approved by these documents alone. The developer must produce a comparative proposal and record recommendations, evidence, trade-offs, and approval-required decisions.

## Required artifacts from the AI design developer
1. Existing implementation audit and risk list.
2. Reference atlas with direct URLs, what to learn, what not to copy, and relevance to River Ways.
3. Three meaningfully different creative routes, each with rationale, palette study, typography study, imagery/art direction, interaction principles, and representative page composition.
4. Comparative evaluation against the constitution and acceptance gates.
5. Chosen-route recommendation, unresolved decisions, and a small responsive prototype before full implementation.
6. Token/component architecture and a page-by-page implementation plan.
7. Tested implementation with desktop/mobile evidence, accessibility and performance checks, and explicit limitations.

## Scope guardrail
The first target is the public River Ways website. Do not silently expand into the Revenue OS, Avenize, or the personal portfolio. Shared principles may inform those products later, but their implementation requires separate scope and decisions.
